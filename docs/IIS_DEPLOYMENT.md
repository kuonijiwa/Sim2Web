# IIS deployment

## Build

Install Node.js 20+ and build from the repository root:

```bash
npm install
npm run build
```

This creates one `frontend/dist` directory per example.  The Vite configurations
use relative asset paths (`base: './'`) and copy that case's `model_cache` into
the build.  Deploy each `dist` directory as a separate IIS application or
static-content directory, for example `/cavern/`, `/flac3d-slope/`, and
`/3dec-slope/`.

## IIS settings

Enable the IIS **Static Content** feature.  Add MIME mappings if the server does
not already provide them:

| Extension | MIME type |
|---|---|
| `.vtp` | `application/octet-stream` |
| `.vtu` | `application/octet-stream` |
| `.json` | `application/json` |
| `.wasm` | `application/wasm` |

No server-side application runtime is required.  Serve `index.html`, the
generated `assets/`, and `model_cache/` from the same application root.  Keep
the directory structure generated by Vite.

For immutable hashed JavaScript/CSS assets, long-lived cache headers are safe.
Use shorter caching (or explicit versioning) for `model_cache/index.json`.

## Verification

Open each deployed `index.html` and confirm:

1. the first model appears without a manual resize;
2. the browser console has no 404, CORS, or MIME errors;
3. field selection updates the cloud map and scalar bar;
4. a SECTION can be selected where implemented;
5. reset and orthographic view controls respond;
6. the 3DEC outer shell starts at 100% opacity.

If a VTP request returns 404, confirm the case-sensitive filename and that
`model_cache/` is beside the deployed `index.html`.  If a request is blocked by
CORS, do not open `index.html` through `file://`; use IIS or another HTTP static
server.  If data downloads but parsing fails, verify the `.vtp`/`.vtu` MIME
mapping and that Git LFS files were pulled rather than left as pointer text.
